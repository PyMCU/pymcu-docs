Conway's Game of Life on a 128x64 SSD1306 I2C OLED: a 32x16 grid of 4x4-pixel cells,
evolving once every 0.1 s. A dead or frozen world holds its last frame for a second, then
reseeds with a fresh random soup and keeps going.

:::note[AVR example]
This page targets the **ATmega328P**. The program is CircuitPython throughout: there is
no MicroPython or native-HAL equivalent shown here, since it is really the unmodified
Adafruit CircuitPython SSD1306 driver stack being exercised.
:::

## What it does

- Seeds a 32x16 cell grid from a small linear congruential generator written in plain
  Python, not the `random` module, which differs between interpreters. The LCG computes
  the identical 31-bit sequence on CPython, CircuitPython and PyMCU, which is also what
  makes the animation below reproducible from an emulator run.
- Steps the grid with the standard Game of Life rule on a toroidal (wrapping) board.
- Draws each live cell as a 4x4 pixel block with `display.fill_rect()`, then calls
  `display.show()` once per generation.
- Reseeds whenever the world dies out or freezes (no cell changed since the last step).

:::note[One grid, not two]
A 128x64 panel's framebuffer alone is 1025 bytes, and the Arduino Uno has 2 KB of SRAM
total. The straightforward port, two full 32x16 grids (`cells` and `next_cells`, the way
the 128x32 version does it), does not fit: the compiler refuses the build (`static data
needs 2288 bytes but atmega328p has 2048 bytes of SRAM`). `step()` below updates a single
grid in place instead, row by row, keeping only two rows of backup, which fits in
1594/2048 bytes of static SRAM, 453 free. See the comment in the code for exactly why two
rows are enough.
:::

## The code

```python
# Conway's Game of Life on the OLED
# Optimized for CircuitPython, using fill_rect and time.sleep
import time
import board
import adafruit_ssd1306

CELL = 4
SEED = 20260921

# Display initialization
i2c = board.I2C()
display = adafruit_ssd1306.SSD1306_I2C(128, 64, i2c)


class Life:
    """Conway's Game of Life on a toroidal width x height grid of cells."""

    def __init__(self, width, height, seed):
        self.width = width
        self.height = height
        self.cells = [[0] * width for _ in range(height)]
        self.rng = seed

    def seed(self):
        # A small LCG in Python, not the random module.
        for y in range(self.height):
            for x in range(self.width):
                self.rng = (self.rng * 1103515245 + 12345) & 0x7FFFFFFF
                self.cells[y][x] = 1 if ((self.rng >> 16) & 3) == 0 else 0

    def step(self):
        # One grid, not cells + next_cells: at 128x64 the two-grid version
        # needs more SRAM than the Arduino Uno has (2 KB total). Each row is
        # updated in place, but computing a row still needs its neighbours'
        # UNCHANGED values, including the row above, which has already been
        # overwritten by the time we get here. So two rows of backup are
        # kept instead of a whole second grid: prev_row (the row just
        # finished, copied forward one row at a time) and first_row (row 0,
        # saved once up front, needed again at the last row because the
        # board wraps top to bottom).
        w = self.width
        h = self.height
        cells = self.cells

        first_row = [0] * w
        for x in range(w):
            first_row[x] = cells[0][x]

        prev_row = [0] * w
        for x in range(w):
            prev_row[x] = cells[h - 1][x]

        old_row = [0] * w
        changed = 0
        for y in range(h):
            for x in range(w):
                old_row[x] = cells[y][x]

            is_last = y == h - 1
            next_y = 0 if is_last else y + 1

            for x in range(w):
                n = 0
                for dx in range(-1, 2):
                    xx = (x + dx) % w
                    next_value = first_row[xx] if is_last else cells[next_y][xx]
                    n = n + prev_row[xx] + old_row[xx] + next_value
                n = n - old_row[x]
                if old_row[x]:
                    new_value = 1 if n == 2 or n == 3 else 0
                else:
                    new_value = 1 if n == 3 else 0
                if new_value != old_row[x]:
                    changed = 1
                cells[y][x] = new_value

            for x in range(w):
                prev_row[x] = old_row[x]
        return changed

    def alive(self):
        for y in range(self.height):
            for x in range(self.width):
                if self.cells[y][x]:
                    return 1
        return 0

    def draw(self, display):
        display.fill(0)
        for y in range(self.height):
            for x in range(self.width):
                if self.cells[y][x]:
                    # OPTIMIZATION 1: use fill_rect to draw the whole cell at
                    # once instead of looping over it pixel by pixel.
                    display.fill_rect(x * CELL, y * CELL, CELL, CELL, 1)
        display.show()


life = Life(32, 16, SEED)
life.seed()
life.draw(display)
generation = 0

while True:
    tick = time.monotonic()
    changed = life.step()
    life.draw(display)
    generation = generation + 1

    if generation % 10 == 0:
        print("generation", generation)

    if changed == 0 or life.alive() == 0:
        # Dead or frozen world: hold the last frame, then a fresh soup.
        time.sleep(1.0)
        life.seed()
        life.draw(display)
        generation = 0

    # OPTIMIZATION 2: rest the processor instead of spinning in a busy wait.
    elapsed = time.monotonic() - tick
    if elapsed < 0.1:
        time.sleep(0.1 - elapsed)
```

## Libraries

The unmodified Adafruit CircuitPython stack, not a single line changed:

| Library                     | Version |
| --------------------------- | ------- |
| `adafruit_ssd1306`          | 2.12.24 |
| `adafruit_framebuf`         | 1.6.12  |
| `adafruit_bus_device` (I2C) | current |

Get the example at [`examples/game-of-life-oled`](https://github.com/PyMCU/pymcu-circuitpython/tree/main/examples/game-of-life-oled)
in the `pymcu-circuitpython` repository; its README covers installing these three packages
straight into the project's own environment with `pip install --no-deps`. Nothing gets
copied into `src/`: PyMCU's CircuitPython compatibility layer resolves them directly from
the installed packages.

## Flash

**13468 / 32768 bytes** (41% of program storage) on `arduino_uno` with `pymcu-compiler`
0.1.0b1 straight from PyPI, the three Adafruit packages installed with `--no-deps` and
nothing copied into `src/`: the whole Game of Life, the SSD1306 driver and the framebuffer
module (no font data is embedded; the program never calls `display.text()`). 1594 bytes of
that program's own SRAM are static (the framebuffer, the grid, the two backup rows), 453
bytes free before the call stack.

This is not a screen recording or a hand-made simulation: every frame comes from decoding
the actual I2C bytes the compiled firmware sends on the wire, through the same
`SET_COL_ADDR` / `SET_PAGE_ADDR` / framebuffer-write protocol a real SSD1306 module would
receive, captured by running the firmware on an emulated Arduino Uno (AVR8Sharp) and
recording the I2C bus. All 46 compared frames were checked pixel for pixel against the
same unmodified source files run under plain CPython, with an identical fake I2C bus
standing in for the hardware: 0 differences. The decoder and the compiled firmware
reproduce the exact board the program computes.

This 128x64 version has not been flashed to real hardware yet. An earlier 128x32 version
of this same program, with 4x4 cells on a 32x8 grid and two full grids rather than one,
did run on a real Arduino Uno wired to a 128x32 SSD1306 module over I2C. Getting it to run
reliably took finding a real compiler bug: see [the write-up](https://pymcu.org/the-oled-that-froze/).

## Build

```bash
cd examples/game-of-life-oled    # in the pymcu-circuitpython repository, after
                                  # installing the Adafruit drivers per its README
pymcu build
pymcu flash --port /dev/cu.usbmodem*
```
